# Редактор БытТех без Supabase

Адаптирован присланный HTML-макет. `/admin/` — редактор **публичного содержимого**,
а не серверная панель с доступом к заявкам и секретам. Установка пакетов,
Supabase и отдельная база не нужны.

## Возможности

- Телефон, подпись города, часы работы и текст кнопки в шапке.
- Первый экран и карточки преимуществ.
- Тексты шагов формы, статуса отключённого приёма и подтверждения.
- Восемь услуг по симптомам и отдельные работы с ценами, сноски.
- Принципы, скидки, преимущества, поломки, шаги, важные условия, районы и CTA.
- Title/description главной и Open Graph.
- Статьи: URL, H1, title, description и полный текст Markdown.
- Добавление, удаление и порядок элементов, сохранение черновика в браузере,
  импорт/экспорт полного JSON, сброс к данным текущей сборки.
- Предпросмотр главной в sandbox-iframe: скрипты, отправка форм и переходы
  отключены. Предпросмотр отдельных статей выполняется после сборки.

Оформление панели основано на присланном макете. Незавершённые функции
дописаны, поля получили связанные label, улучшены мобильные размеры кнопок.
Кнопка-заглушка «Опубликовать» заменена действием «Скачать изменения».
Интерфейс ясно показывает, что сохранение локальное и рабочий сайт ещё не менялся.

## Источники и сборка

`content/site.json` — источник текстов и списков главной. `web/index.html` —
шаблон с оформлением, изображениями, SVG и логикой формы. Для изменений текста
используйте JSON: сборщик подставляет данные из него поверх шаблона.
`content/articles.json` — статьи. Публичные реквизиты и разрешение приёма заявок
по-прежнему задаются отдельной подтверждённой конфигурацией сборки/сервера.
Переменная OWNER_PHONE, если задана, имеет приоритет над телефоном из редактора.

```sh
python3 deploy/build_pages.py /tmp/byttech-editor
python3 -m http.server 8018 --bind 127.0.0.1 --directory /tmp/byttech-editor
```

Откройте `/admin/` на этом сервере. Сборщик создаёт `admin/defaults.json`
из актуальных источников и `admin/schema.json` из структуры шаблона.
Черновик localStorage не синхронизируется между устройствами. Сообщение панели
предупреждает о загруженном локальном черновике; во вкладке «Публикация» можно
скачать его или сбросить к данным текущей сборки. JSON служит переносимой копией.
Панель не загружает старый ключ из присланного примера, содержащий поле leads.

## Применение изменений

1. Отредактировать данные, проверить предпросмотр и скачать `byttech-content.json`.
2. Проверить экспорт сборкой **без изменения исходников**:

   ```sh
   SITE_URL=https://ricoellong.github.io/byttech-site \
     python3 deploy/build_pages.py /tmp/byttech-changed --production --content byttech-content.json
   ```

3. Применить проверенный JSON в локальном checkout:

   ```sh
   python3 deploy/apply_content.py byttech-content.json
   python3 -m unittest discover -s tests -v
   node --check web/request-form.js
   git diff -- content/site.json content/articles.json
   ```

   Скрипт полностью проверяет документ до изменения файлов. Ошибочный импорт
   не изменяет исходники. В репозиторий не добавляется сам скачанный файл.
4. После проверки сделать commit/push в `main`. Существующий GitHub Actions
   выполнит проверки, соберёт HTML и опубликует GitHub Pages. Пользовательская
   авторизация GitHub используется через обычные средства Git; токен в браузер
   редактора не передаётся. Публикация из редактора одним кликом не реализована:
   для неё нужен отдельно защищённый серверный механизм записи в репозиторий.

## Защита данных и ограничения

Панель не является приватным сервером: открыть её на GitHub Pages сможет любой.
Посетитель может менять только собственный локальный черновик. Из панели нет
API записи в репозиторий и доступа к заявкам. Доступ к публикации остаётся у
владельца GitHub. Пароли, токены, заполненные реквизиты сервера и клиентские
контакты не следует помещать в черновики и JSON.

Вкладка «Заявки» объясняет отсутствие подключения; вымышленные заявки и CRUD
в localStorage не добавлены. Включение формы, обязательное согласие и версия
`pd-2026-11-09-v1` не управляются этим редактором. Поле enabled из стороннего
JSON отклоняется. Правовые ссылки остаются в форме, редактирование правовых
документов через панель не предусмотрено.

При импорте и сборке проверяются версия, состав полей, размеры, формат телефона,
уникальные безопасные URL статей и ссылки Markdown. Тексты экранируются при
сборке и вставляются через textContent в предпросмотре. Необработанный HTML
из JSON не исполняется.

Существующий шаблон остаётся источником декоративных иконок карточек. Для
новых карточек используются имеющиеся оформления. Дополнительные изменения
изображений и общего дизайна требуют отдельного редактирования шаблона.
Карта сайта и canonical формируются обычным production-сборщиком; admin-страницы
содержат noindex/nofollow и не попадают в sitemap.

## Проверено локально

- 12 Python-тестов: базовые проверки сайта, применение JSON в сборке,
  изменение телефона/цен/списков, добавление статьи, экранирование,
  отклонение частных полей и небезопасных ссылок, сохранность исходников
  при ошибочном импорте, применение валидного экспорта.
- Chromium: ввод, сохранение после перезагрузки, sandbox-предпросмотр, прайс,
  добавление статьи, скачивание и обратный импорт JSON, отклонение неправильного
  JSON, вкладка заявок без персональных данных, ширины 320/375/1440.
- Выгруженный браузером JSON дополнительно принят production-сборщиком.
- Публичные страницы и форма проверены отдельным browser-smoke.

Команды браузерных проверок (нужны доступные Playwright и Chromium):

```sh
REVIEW_URL=http://127.0.0.1:8018 node tests/editor-browser.cjs
REVIEW_URL=http://127.0.0.1:8018 node tests/browser-smoke.cjs
```

Панель публикуется штатным workflow GitHub Pages по адресу
https://ricoellong.github.io/byttech-site/admin/. Публикация редактора не
включает приём заявок и не даёт браузеру права записи в репозиторий.
