Отдельный репозиторий сайта. Актуальные страницы перенесены из
`RicoElLong/bot-tech`, ветка `feat/website-requests-20261101`, коммит
`62bbcbb00bd179b474e70f12fa826c7f308fb80f` от 09.11.2026.

## Что находится здесь

- `web/index.html` — главная страница, оформление, встроенные изображения и MAX.
- `web/request-form.js` — форма записи и отправка на `POST /api/requests`.
- `web/privacy.html`, `consent.html`, `legal.html`, `work-order.html` — документы сайта.
- `web/PRICE_SOURCE.md` — происхождение прайса и условия его проверки.
- `tests/` — существующие проверки контактов, MAX и цен.
- `LEGAL_LAUNCH_CHECKLIST_2026.md` — перенесённый перечень вопросов перед релизом.

Telegram-бот, API, очередь уведомлений и база остаются в
[RicoElLong/bot-tech](https://github.com/RicoElLong/bot-tech).
Код бота, настройки с секретами, база и история общего репозитория сюда не копируются.

## Проверка на Windows

Из корня этого репозитория в PowerShell, при установленном Python 3.12+ и Node.js:

```powershell
python -m unittest discover -s tests -v
node --check web/request-form.js
```

Для этих проверок установка Python-пакетов не нужна. Это проверки файлов сайта;
они не проверяют доставку Telegram и работу серверной базы.

## Как сайт связан с сервером

Текущая версия — серверные HTML-шаблоны. `webapp.py` из репозитория бота
подставляет подтверждённые реквизиты вместо `{{OWNER_*}}`, выдаёт страницы
и принимает заявки на том же домене. Контракт формы и версия согласия
`pd-2026-11-09-v1` сохранены без изменений.

Не включайте GitHub Pages для этих исходников: обычный статический сервер
не подставляет реквизиты, не реализует `/api/requests` и маршруты документов.
Создание репозитория само по себе не публикует и не запускает сайт.

При будущем развёртывании на VPS используйте отдельный каталог запуска:

1. Подготовьте проверенную версию сервера из `bot-tech` с поддержкой текущего
   `/api/requests`. Его ветка `main` на дату переноса содержит другой обработчик.
2. Поместите серверные файлы в каталог запуска вне обоих Git-репозиториев.
   Подкаталог `web` в этом каталоге должен содержать содержимое `web/` из
   `byttech-site`; на Linux допустима символическая ссылка на этот каталог.
3. Секреты и реквизиты храните в `.env.local` каталога запуска. Данные и резервные
   копии должны оставаться за пределами репозитория сайта.
4. Настройте HTTPS, разрешённый origin, реквизиты и условия запуска по
   документации сервера и юридическому чек-листу.
5. Проверьте все страницы и тестовую заявку до переключения рабочего домена.

Таким образом, изменения страниц ведутся в `byttech-site`, а серверный код —
в `bot-tech`. Развёртывание связывает две проверенные версии. При этом перенос
исходников не требует изменений работающего бота.
