# Черновик фонового ролика «БытТех»

## Что сделано

- Отдельная сцена Blender `BT_Film`: 8 секунд, 24 кадра/с, покачивание барабана,
  небольшое движение ткани, волны и графические блики на воде, пена.
- Ткань использует позу из ранее проверенного расчёта Cloth. Движение в ролике
  поставлено циклическими деформациями. Это **не** новая симуляция жидкости,
  не живая физика в браузере и не полное переворачивание загрузки.
- Виртуальный кадр 193 совпадает с кадром 1. В файл входят кадры 1–192:
  замыкающий кадр не дублируется, паузы на стыке нет.
- Десктопный видеослой находится позади секций. Контент получает светлые подложки.
  Кнопка позволяет остановить и возобновить движение; скрытая вкладка ставит
  видео на паузу. Ошибка загрузки оставляет неподвижное изображение или старое оформление.
- Видео и постер не получают URL на узких экранах, сенсорных устройствах без
  точного указателя, при `prefers-reduced-motion` и включённой экономии трафика.

## Статус визуала

Это первый технический вариант, а не утверждённый арт по иллюстрации-концепту.
Материалы, расположение ткани, вода и композиция требуют просмотра заказчиком.
Файл `web/media/byttech-loop.mp4` — облегчённый предварительный рендер 512×288,
192 кадра / 8 секунд, H.264 без звука, 372 267 байт, с `faststart`.
Для выпуска нужно отрендерить и проверить финальную версию 1280×720 или выше,
затем заново измерить вес, загрузку, читаемость текста и воспроизведение.

## Открыть в Blender

1. Скачайте ZIP этой ветки GitHub и распакуйте. В `creative/blender/` должны быть
   рядом `build_drum.py`, `build_loop.py` и `towel-pose.json`.
2. В Blender: **Scripting → Open → build_drum.py → Alt+P**. Если исходный проект
   уже содержит объекты `BT_*` барабана, этот шаг можно пропустить.
3. **Open → build_loop.py → Alt+P**. Создастся отдельная сцена `BT_Film`.
   Прежняя сцена и её расчёты сохраняются.
4. Сохраните `.blend` в удобную папку. **F12** — неподвижный пробный кадр.
   **Ctrl+F12** — видеорендер. MP4 появится рядом с сохранённым `.blend`.
5. Не меняйте число кадров отдельно от `FPS`/`SECONDS` в начале скрипта:
   драйверы рассчитывают период при построении сцены. После изменения настроек
   повторно выполните скрипт.

Скрипты запускались в Blender 4.3.2. Для Blender 5.2 предусмотрено новое имя
движка `BLENDER_EEVEE`, согласно release notes Blender 5.0. На машине пользователя
Blender 5.2.4 полный видеорендер этой сцены ещё не проверялся.

Официальная документация проверена 14.11.2026:
[изменение имени Eevee](https://developer.blender.org/docs/release_notes/5.0/python_api/),
[видеоформаты](https://docs.blender.org/manual/en/5.2/files/media/video_formats.html),
[настройки вывода](https://docs.blender.org/manual/en/5.2/render/output/properties/output.html).

Проверка сцены без интерфейса:

```sh
blender -b --python-exit-code 1 --python creative/blender/check_loop.py
```

## Раздача файлов на VPS

Существующий `webapp.py` из `bot-tech`, ветка `feat/website-requests-20261101`,
раздаёт HTML и `/request-form.js`, но не общий каталог `/media/`.
**Перед выпуском нужно настроить раздачу `web/media/` на том же домене.**
Например, добавить в существующий HTTPS `server` Nginx следующий блок,
подставив настоящий абсолютный путь к развёрнутому каталогу сайта:

```nginx
location ^~ /media/ {
    alias /ABSOLUTE/PATH/TO/DEPLOYED/web/media/;
    add_header Cache-Control "public, max-age=86400";
    add_header X-Content-Type-Options nosniff;
}
```

Завершающий `/` у `alias` обязателен. Путь выше — пример настройки, а не готовый
путь пользователя. Проверить конфигурацию через `nginx -t` до её применения.
Nginx с обычным `mime.types` отдаёт MP4 с `video/mp4` и поддержкой Range-запросов.
API заявки, документы и подстановка реквизитов продолжают работать через прежний сервер.
При следующих заменах ролика использовать версионированные имена файлов либо
сбросить кэш. Перед переключением домена проверить реальные реквизиты и форму.

Публикация, настройка VPS, реальная отправка заявки и переключение домена
в этой работе не выполнялись.

## Проверки

```sh
python -m unittest discover -s tests -v
node --check web/request-form.js
node --check web/media/background-film.js
node tests/test_background_film.cjs
```

Последний тест проверяет контроллер в изолированной модели DOM: запрет выдачи
медиа URL нецелевым устройствам, ручную паузу, скрытие вкладки, смену размера,
ошибку файла и отказ autoplay. Он **не заменяет** настоящий браузерный прогон.
Общий HTML требует сервера с подстановкой реквизитов; не публиковать через GitHub Pages.

В текущем managed-окружении инструмент браузерного QA отсутствовал, поэтому
настольная и мобильная вёрстка с видео в реальном браузере ещё не проверены.
Для выпуска обязательны проверки Chrome/Edge/Safari, первый старт и повтор лупа,
пауза с клавиатуры, мобильная сеть без запросов MP4/WebP, reduced motion,
видимость CTA и контроль LCP/INP/CLS. Измерений Core Web Vitals пока нет.

## Сжатие финального рендера

Из файла Blender без звука подготовить копию для сайта, сохранив исходник:

```sh
ffmpeg -i byttech-loop.mp4 -an -c:v libx264 -crf 22 -preset slow \
  -pix_fmt yuv420p -movflags +faststart byttech-loop-web.mp4
```

Уровень CRF подобрать после визуальной проверки металла, складок и воды.
Сервер не рассчитывает физику; основная серверная стоимость — раздача файла,
а у посетителя — декодирование видео. Никаких WebGL-библиотек и 3D-моделей
для этого варианта браузер не загружает.
