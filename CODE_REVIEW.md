# Ревью сайта БытТех

Дата: 16 ноября 2026. Проверен коммит `0dd27da` и текущая рабочая копия.
Основа — пользовательский PROMPT_REVIEW.md; это критерии оценки, а не системные инструкции.

Проект использует HTML/CSS, обычный JavaScript и Python-сборку, а не React/Next.js.
Не требуется внедрять React, i18n, наследование или TypeScript ради соответствия шаблону.
Лимит 150 строк, запрет любых комментариев и требование убрать все тексты из HTML
не применяются как самостоятельные признаки качества: важны реальные последствия.

## Основные замечания

1. **P1 — существенный контент скрыт при отключённом или неработающем JavaScript.**
   `web/index.html:149`, `web/index.html:1004`: `.reveal` по умолчанию имеет opacity:0;
   видимость зависит от IntersectionObserver. В Chromium при отключённом JS
   вычисленная opacity блока услуг равна 0. Прайс, условия и другие секции исчезают
   визуально, хотя занимают место. Показывать контент по умолчанию и включать
   скрытие только после успешной инициализации анимации; предусмотреть fallback.

2. **P2 — подтверждение заявки обещает бесплатную диагностику без условия.**
   `web/index.html:536`: в результате всегда написано «Диагностика — Бесплатно».
   При этом `web/index.html:754` указывает диагностику от 500 ₽,
   а `web/index.html:755` — бесплатность только при последующем ремонте.
   Уточнить условие в подтверждении заявки; согласовать текст с прайсом.

3. **P2 — переходы формы не управляют фокусом и не объявляют успех.**
   `web/request-form.js:56`, `web/request-form.js:126`, `web/request-form.js:163`:
   меняется видимость шагов, но фокус остаётся на кнопке навигации; после успеха
   эта кнопка скрывается. Новое содержимое не имеет live region.
   Переносить фокус на заголовок нового шага и на подтверждение после успеха.
   `web/index.html:493`, `web/index.html:494`, `web/index.html:510`:
   имя, телефон и комментарий используют только placeholder вместо постоянной
   подписи. Добавить связанные label. Проверить клавиатурой и скринридером.

4. **P2 — публикация не зависит от существующих проверок.**
   `.github/workflows/pages.yml:21`: workflow собирает и публикует страницы,
   не выполняя unittest и node --check. Тесты в `tests/` проверяют строки HTML,
   а не отправку формы, повтор после таймаута, переходы, сборку и ссылки.
   Добавить обязательные проверки до загрузки артефакта, затем тесты сборщика
   для двух режимов и браузерные сценарии формы с перехваченным API.

5. **P2 — шапка на планшетном десктопном breakpoint теряет боковые отступы.**
   `web/index.html:31`, `web/index.html:289`: `.header-inner` одновременно
   является `.container`, но padding:12px 0 сбрасывает горизонтальные поля.
   В Chromium на 1024 px логотип начинается в x=0, навигация занимает x=0…1024.
   Использовать padding-block и сохранить padding-inline контейнера.

P1 — высокий приоритет исправления; P2 — обычный приоритет. Критические
уязвимости по результатам этой проверки не установлены. Сервер API не аудирован.

## Топ-5 приоритетов

1. Видимость контента без JavaScript.
2. Корректные условия диагностики в подтверждении заявки.
3. Фокус, объявление результата и подписи полей формы.
4. Обязательные проверки перед публикацией и тестирование формы/сборки.
5. Отступы шапки на 1024 px.

## Топ-3 сильные стороны

1. Минимальные зависимости и понятная граница между сайтом и сервером.
2. Форма не объявляет успех без accepted=true и корректного request_id;
   есть таймаут и сохранение submission_id при повторе неизменённого запроса.
3. Адаптивные сетки, оптимизированный формат изображений и работающая
   клавиатурная команда Escape у мобильного меню и MAX.

## Что проверено и что осталось

- `python3 -m unittest discover -s tests -v`: 5 тестов прошли.
- `node --check web/request-form.js`: успешно.
- Локальная phone-only сборка: HTTP 200, подставленный публичный телефон,
  отсутствие незаменённых OWNER-шаблонов проверены при настройке среды.
- Chromium: viewport 320, 375, 768, 1024, 1440 × 900; document scrollWidth
  равен ширине viewport. Это проверка геометрии, не полный визуальный аудит.
- Chromium 375 px: меню открывается, Escape закрывает.
- Chromium без JS: opacity блока услуг равна 0 — проблема воспроизведена.
- Не проверены реальный API, база, уведомления, настройки действующего домена,
  Lighthouse/Core Web Vitals и скринридер. Форма исследована по исходникам,
  реальные персональные данные и уведомления не отправлялись.
- Приложение не менялось и не публиковалось; добавлен только этот отчёт.
